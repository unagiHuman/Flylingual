## 1. 企画の一文

**小さなハエと話し合いながら、机の上の巨大な日用品を歩いて登り、窓辺の角砂糖を目指す。落ちても、二人で覚えた歩き方は残る。**

プレイヤーは道を見渡せるが、ハエの足元の感触までは分からない。ハエは目の前の足場を感じ取れるが、山全体の道筋は把握できない。互いの情報を持ち寄り、進み方を決める「一人と一匹の登山ゲーム」とする。

ユーザーが挙げた Getting Over It の方向性を、本企画では「身体を扱う難しさ」「連続した上り道」「落下による進行の喪失」「反復で身につく攻略」と解釈する。そこに、同じ失敗を経験し、次の作戦を相談できる相棒を加える。

| 項目 | 提案 |
|---|---|
| ジャンル | 会話で協力する、高難度の歩行・登攀ゲーム |
| プレイ人数 | 1人＋会話するハエ1匹 |
| 想定環境 | PC。音声と字幕を基本に、テキスト入力・短い定型指示も用意 |
| 想定プレイヤー | 身体操作の習熟、失敗からの攻略、キャラクターとの関係を楽しむ人 |
| 舞台 | ひとつの机から窓辺まで。日用品が山や谷に見える縮尺 |
| ゴール | 最上部の皿にある角砂糖へ、歩いて到達する |
| 想定規模 | 本編1コース・6区間。初見60〜120分を仮目標とし、試遊で見直す |
| 最初の試作 | 机上の導入→定規橋→落下後の再挑戦。初見10〜15分程度 |

## 2. プレイヤーに届ける体験

### 「動かす」から「息を合わせる」へ

序盤は「右へ」「止まって」と伝えるだけで精一杯。中盤には「ここは早めに止まろう」「まず広いところで向きを変えよう」と、ハエの歩幅や止まるまでの動きを踏まえて話せるようになる。終盤では、少ない言葉で通じること自体が成長の実感になる。

難しさの中心は、進路選び、旋回する場所、止まり始める位置に置く。言い間違いを罰することや、決まった台詞を当てることを攻略の中心にしない。

### 失敗しても、一緒にいた時間が残る

大きく落ちれば悔しい。しかしハエは、前の挑戦と今回の違いに短く触れる。

> ハエ「さっきより橋の真ん中まで行けたね。」  
> プレイヤー「曲がるのが遅かった。次は手前で向こう。」  
> ハエ「うん。広いところで向きを合わせよう。」

関係性は好感度の数値より、共有した出来事への言及や、プレイヤーが教えた呼び名で表現する。励ますと摩擦や脚力が上がる仕組みは採用せず、会話が判断と意思疎通を改善する設計にする。

### ハエの大きさだから生まれる冒険

本の背は尾根、定規は橋、マグカップの陰は休憩所になる。実寸では近い砂糖が、ハエには遠い山頂に見える。少し登るたび、以前苦労した道が下に小さく見える景色を作る。

飛行は本企画の移動手段に含めない。「今日は自分の脚であそこまで行きたい」というハエの小さな挑戦を動機の第一案とする。飛べない理由を説明する長い導入は設けず、歩いて目指す約束を最初に共有する。

## 3. 基本ルールと操作

### 1回の攻略の流れ

1. **見る：** プレイヤーが次の足場、分岐、落ちた先を見渡す。
2. **聞く：** 必要ならハエに足元や進み方について尋ねる。
3. **決める：** 「広い左の道」「橋に入る前に向きを変える」など作戦を立てる。
4. **歩く：** 前進・左右旋回・停止を短く指示し、身体の動きを観察する。
5. **確かめる：** 安定した足場で止まり、成功や失敗を次の判断に生かす。

### 操作の第一案

主操作は音声による短い行動指示とする。「前へ」「右を向いて」「止まって」などを受け付ける。字幕欄と同じ意味の定型入力を用意し、声を出せない環境でも攻略できるようにする。自由な相談と短い操作指示を同じ会話体験にまとめる。

「定規の根元まで行って」のような地点指定は追加候補であり、最初の試作は既存の6 Actionに相当する指示で成立させる。「右」はハエ自身の右に統一し、画面上にも進行方向を小さく表示する。

雑談や仮定の相談を勝手に移動命令にしない。「あっち」など対象が不明な指示は、移動を追加せず聞き返す。聞き返しが必要な場合は停止を要求し、停止確認前に安全になったとは伝えない。確認のやり取りは主に広い足場で行える配置にする。

通常の停止には身体の余動がある前提で、早めに伝えることを学ぶ。緊急停止ボタンは別に常設し、出力を止める機能として扱う。空中で身体を固定したり、落下前の位置へ戻したりする機能にはしない。

試作中は手動入力との比較も行えるが、操作権は明示的に切り替える。移動中に会話とキー入力を競合させない。

### 勝利・落下・中断

- 角砂糖の周囲にある到達領域へ入り、安定して留まればクリア。静止判定の許容値は歩行検証後に決める。
- 通常の落下は下の足場へ物理的に着地し、その場所から続ける。残機やダメージは設けない。
- コース外へ落ちた場合は机上の開始地点へ復帰する。配置と復帰方法は物理検証の対象とする。
- 通常モードは区間ごとの自動チェックポイントを置かず、地形上の受け止め場所で損失を調整する。
- 終了時の中断保存を用意する。再開時は同じ進行状態を復元し、足場が不安定なら直前の安定状態を復元する仕様を検証する。
- 別の練習モードでは、到達済み区間から反復できるようにする。

## 4. 会話が攻略に必要になる仕組み

会話の価値を「命令」「足元の情報」「共同作戦」「共有記憶」の4つで作る。毎回話しかける義務はなく、知っている区間は短い指示だけで再挑戦できる。

| 会話の役割 | 場面と発話例 | プレイヤーの判断に起きる変化 |
|---|---|---|
| 足元の情報を得る | 「この先どう？」「今の足元は少し滑ってる」 | 狭い近道を避ける、広い場所で止まる |
| 作戦を共有する | 「橋に入る前に向きを合わせよう」「ここで右だね」 | 安全な場所で旋回を終え、橋上の修正を減らす |
| 失敗を振り返る | 「何がまずかった？」「曲がりながら端に近づいていたよ」 | 次は進路変更と前進を分けて試す |
| 呼び名を共有する | 「あの広い本を休憩所って呼ぼう」 | 以後の会話で場所を指しやすくなる |
| 気持ちを共有する | 「落ちたけど、もう一回行こう」「さっきの橋までは行けたね」 | 再挑戦する理由と相棒への愛着が生まれる |

**プレイヤーは大局、ハエは局所を担当する。** ハエは正解ルートや未訪問の足場の安全性を知っている存在にはしない。初めての場所では「まだ分からない」「ここから見えるところなら」と限界を伝える。

足元の情報は、接触・滑り・傾斜などUnityで取得した観測を根拠にする。匂い、風の予兆などを採用する場合は、別途ゲーム用センサーとして定義する。これらを神経活動から読み取れた情報とは扱わない。

### 会話と地形のセット例：定規橋

プレイヤーには橋の出口が右にずれて見える。ハエは橋に入った後、足元の滑りを報告する。橋の上で大きく旋回すると横へ流れやすいため、入口の広場で出口に向きを合わせてから進む方が安定する。

失敗後の会話では、観測できた「橋の上で旋回した」「横へずれた」を伝える。原因を断定できなければ「曲がる位置を変えて試そう」と提案する。次の挑戦でプレイヤーが手前から向きを調整できれば、会話が実際の攻略に結びついたと言える。

定規の傾斜や幅は、採用中の物理でこの差が再現できる範囲に調整する。素材の見た目だけで、滑りやすさが実装済みとみなさない。

### 記憶と人格の扱い

記憶するのは到達地点、転落地点、直前の行動、プレイヤーが付けた呼び名、合意した作戦など、実際に共有した出来事とする。落下しても保持し、新規ゲームではリセットする。生の音声や全文会話の恒久保存を前提にしない。

ハエの人格は、好奇心があり、砂糖に目がなく、少し強がるが失敗を責めない方向を提案する。発話は移動中なら一言、休憩所なら少し長くできる。同じ落下で同じ説教を繰り返さず、雑談頻度とヒント量を調整できるようにする。

人格・関係性・記憶はゲーム上の表現である。神経由来の状態表現は共通設計に従い、観測できない感情や意識の存在を事実として説明しない。

## 5. レベル全体：机から窓辺への一本道

大きな流れは一本とし、途中に「広く長い道／狭く短い道」の局所分岐を置く。ゴールは序盤から見える位置に置き、登るほど角砂糖の輪郭が大きくなる。

| 区間 | 地形と目的 | 学ぶこと | 会話の役割 | 落下した場合 |
|---|---|---|---|---|
| 1. パンくずの平原 | 広い机上。紙の緩い坂から低い本へ | 前進、旋回、早めの停止 | 呼びかけと返答。止まれた事実の確認 | 同じ広場へ。損失はごく小さい |
| 2. 定規の橋 | 2冊の本をつなぐ緩い上り橋。入口と出口は広い | 橋へ入る前の向き合わせ | 足元の報告と、失敗後の作戦変更 | 下の開いた本へ。短く戻って再挑戦 |
| 3. 本の山脈 | 本の表紙と紙片の斜路。広い迂回路と狭い近道 | 経路選択、連続する曲がり角 | 見通しと足元情報を持ち寄って道を選ぶ | 区間1または2の既知の足場へ |
| 4. カップの回り道 | マグカップを囲う紙帯の通路。外側は見やすく、内側は足元が隠れやすい | カメラで確認し、必要なら止まって尋ねる | 見えにくい近傍について報告する | 本の山の中腹へ |
| 5. 窓辺の細道 | 窓枠へつながる長い斜路と細い折返し。途中に休憩ポケット | 狭さ、停止、旋回の複合 | 二人で決めた短い言葉を使って集中する | 大きく落ち、区間2〜3へ戻る可能性 |
| 6. 砂糖の頂 | 最後の短い橋から、広い皿へ出る | これまでの基本を落ち着いて使う | 最後の一歩と到達を共有する | 最終手前の棚へ。終点で突然の新ルールを出さない |

カップの縁への吸着歩行、垂直壁、天井、ジャンプ、飛行は初期必須にしない。本の高低差は連続した斜路でつなぐ。紙帯も歩行可能な支持面として設計し、見た目の立体感だけを先行させない。

### 難易度の上げ方

難易度は「足場の幅」「曲がる余裕」「傾斜」「見通し」「失う進行」の組合せで作る。新しい条件はまず広い足場と短い落下で紹介し、理解した後で損失を増やす。一度にすべてを厳しくしない。

落下経路もコースとして設計する。落ちる途中に過去の場所が見え、広い本や机上に受け止められるようにする。初期の損失は数十秒、終盤の大落下は習熟時で数分を暫定目安とし、実測で調整する。

休憩場所はおよそ2〜3分ごとを仮目標に配置する。ここでは旋回、会話、次の道の観察ができる。休憩所への到達と復帰用チェックポイントは別の仕組みとする。

## 6. 最初の試作コース

本編を作り込む前に、**「会話によって二度目の歩き方が変わるか」**を短いコースで確かめる。

### 配置案

```text
低いゴール皿 ← 広い出口 ← 定規橋 ← 向き合わせ広場
                                  ↑
                         紙の緩い坂 ← 開始広場

定規橋の下：開いた本の受け皿 → 紙の坂の手前へ歩いて復帰
```

試作のゴールは机上の低い位置に置く。本編の窓辺は遠景の目印として示せるが、まず一つの橋を往復可能な地形として成立させる。

以下の寸法はブロックアウト用の初期値であり、歩行可能性の保証ではない。Bを脚を含む通常歩行時の横幅、Lを体長とする。

| 要素 | 初期寸法の目安 | 設計意図 |
|---|---|---|
| 開始広場 | 8B × 8B以上 | 指示と身体の反応を余裕をもって見る |
| 入口・出口の広場 | 6B × 6B以上 | 旋回と停止を狭い橋から分離する |
| 定規橋 | 幅2.5〜3B、長さ8〜12Lから調整 | 通過する余裕を残しつつ横ずれを意識させる |
| 斜路 | まず平面で確認後、0〜5度の範囲から調整 | 登坂未成立なら平面の同じ課題で検証する |
| 橋下の受け皿 | 予想される落下範囲を覆う広い面 | 落下後すぐ作戦を試し直せるようにする |

橋の入口は斜めに接続し、直進だけでは出口を向かない形にする。ただし橋上での細かな修正を完全に不可能にせず、複数の歩き方を許容する。

止まり始める位置は、音声指示からの停止時間と余動距離を測って決める。安全余白は「通常の会話・処理遅延中に進む距離＋停止後の余動距離＋身体の余裕」で見積もる。単発の最良値を採用せず、繰り返し計測したばらつきを含める。

### 試作に必要なもの

- 歩行・左右旋回・通常停止、落下、受け皿からの復帰、ゴール判定。
- 広場、紙の坂、定規橋、低い皿のグレー形状。
- 短い行動指示、字幕、定型入力、緊急停止。
- 接触・横ずれなど、実際に取得できる観測に基づく短い報告。
- 今回の転落地点と直前の行動を保持し、次の挑戦で一度だけ参照する会話。

自由な名前付け、長期的な人格変化、動的な風、分岐の多い本編、細かな美術は試作評価後に進める。

## 7. 画面・音・演出

カメラはハエの斜め後方を基本とし、次に進む足場と足元を同時に見せる。安全な広場では回転とズームで全体を調べられる。狭い場所で急に視点が反転しないようにする。

通常画面に置く情報は、ハエの身体、進行方向、短い字幕、受け付けた指示、会話と操作の状態を中心にする。「聞き取った」と「実際に動いた」は混同させず、受付は文字、動作の確認は身体と必要最小限の状態表示で伝える。内部診断は設定画面にまとめる。

足が滑る音、紙面を歩く音、着地音で足元の変化を補助する。音だけに依存せず、姿勢や小さな表示でも分かるようにする。ハエを隠す大きな吹き出しや、難所の途中で操作を遮る会話選択肢は置かない。

落下中は長い台詞を入れず、着地後に必要なら反応する。ゴールでは広い皿に出て緊張を解き、砂糖を味わう短い演出と、そのプレイで実際に起きた出来事への一言で締める。

## 8. 面白さと成立性の評価

以下は今後の試遊計画と仮の採用基準であり、検証済みの結果ではない。

### 先に通す成立条件

実環境で前進、左右旋回、停止、再開を繰り返し、意図と逆の旋回や継続不能な遅延がないか確認する。動作のばらつきが、試作の足場と安全余白に収まらなければ地形の高難度化へ進まない。

会話の認識失敗、切断、古い指示の遅延実行を、プレイヤーの操作ミスやハエの気分として演出しない。障害時は既存の出力抑止を維持し、中断を表示する。障害中の落下を通常の進行損失に数えず、直前の安定状態から再開する復元仕様を追加課題とする。

### 少人数の試遊で確かめること

最初は5人程度で観察する。数値は傾向を見るための仮基準とし、統計的な証明とは扱わない。

| 検証したいこと | 見る行動・聞く質問 | 初期の判断目安 |
|---|---|---|
| 会話が攻略を変えるか | 足元の報告後、旋回や停止の位置を変えたか | 5人中4人が一度以上、報告を根拠に作戦を変える |
| 失敗が理解できるか | 「なぜ落ちたと思う？ 次はどうする？」 | 5人中4人が、変える行動を具体的に言える |
| 再挑戦したくなるか | 最初の落下後、自分から再挑戦するか | 5人中4人が再挑戦し、会話待ちが妨げにならない |
| 相棒として感じられるか | 「ハエと一緒に攻略したと感じた場面は？」 | 具体的な共有体験が出る。雑談の好感だけで判定しない |
| 難しさが公平か | 落下直前の指示、受付、身体、足場を照合 | 認識・遅延・接続不良による失敗は地形難度と分けて修正する |

会話の効果を見たい場合は、操作指示だけの条件と、足元報告・失敗の振り返りを加えた条件を比較する。移動性能と入力手段をそろえ、順序を入れ替えて学習の影響を減らす。

落下回数とクリア時間だけでなく、同じ地点で同じ失敗を繰り返す回数、作戦変更、会話待ちで中断した回数も記録する。評価のための録音や全文会話収集は必須にしない。

## 9. 既存プロジェクトとの接続と制作順

### 資料から確認した土台

既存の進捗資料には、The Sugar Runの開始・ゴール・落下・再開始の枠組みと、机、本、カップ等を使う画面が記録されている。これを舞台と目的の土台にできる。ただし当該記録はReplayベースの過去の成果で、現在のWindows実Brainによる本企画の完走を証明するものではない。

Unityネイティブ会話版には音声・字幕・「声で操作」の仕組みが記載されている。一方、同資料では身体操作、会話との継続併用、実マイク品質などの受入れが未完了とされている。本企画で必要な足元の報告、共有記憶、ランドマークの呼称、障害時の状態復元は追加設計・検証事項とする。

身体への指示は既存6 Actionを起点とし、Brainの神経出力と既存decoderを経由する。会話機能の都合でmotorを直接生成したり、人格設定で物理性能を変えたりしない。

### 制作の順番

1. **歩行の基準を作る：** Windows実Brainで旋回・停止・余動と音声遅延を把握し、安全に試せる足場幅を決める。
2. **短い地形を成立させる：** 広場と橋を組み、歩いてゴール、落下、復帰が実際に成立することを確認する。
3. **攻略に使う会話を足す：** 観測に基づく報告と一度の失敗記憶を加え、二度目の行動が変わるか試遊する。
4. **縦方向へ拡張する：** 操作可能な斜路で本の山を作り、落下先と再登攀の時間を調整する。
5. **本編の関係性を育てる：** 呼び名、区間をまたぐ記憶、会話頻度、終幕を加え、美術と音を整える。

動作検証はリポジトリの現行方針に従い、Windows上の実BrainへのLive接続で行う。本書の作成ではUnity操作、シーン変更、Brain起動、実API呼び出しは行っていない。

### 現時点の提案判断

まず「会話を主操作とする短い定規橋」を作り、ハエの報告を聞くと攻略が変わることを最優先で検証する。入力遅延のため会話で連続歩行することが成立しない場合は、足場と停止地点の設計を見直す。それでも成立しなければ、手動歩行＋会話での相談へ企画判断を戻す。後者へ移る際は操作体験の変更として扱い、会話主操作が完成したとはみなさない。

**この企画の成功は、山頂に着いたプレイヤーが「操作に慣れた」に加えて、「このハエとなら登れるようになった」と感じられること。**
