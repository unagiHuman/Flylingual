# プレイ画面 インターフェース仕様書

作成日：2026-09-13（JST）  
版：0.2／実装反映版  
対象：Flylingual／Unityでゲームをプレイするための画面

## 1. 画面の目的

プレイヤーが、ハエの行動、脳の活動、思考・気持ちのキャラクター表現を、ひとつのプレイ画面で同時に見られるようにする。

プレイ画面は、以下の3領域で構成する。

| 領域 | 表示するもの | プレイヤーが把握すること |
|---|---|---|
| ゲーム画面 | ゲーム映像全体を縮小して収めた映像 | ハエがどこにいて、何をしているか |
| ハエの脳シナプス発火確認画面 | ハエの脳・神経活動の可視化 | 脳のどこで、どのような活動が起きているか |
| ハエリンガルUI | デフォルメしたハエのポンチ絵を中心とした表現 | ハエが何を考え、どのように感じているように見えるか |

本書は画面仕様と実装済み範囲を整理する。Editorでの実表示確認は完了しているが、Windows Playerビルドによる受入れ完了を示すものではない。

## 2. 要件の根拠と確定範囲

### 2.1 ユーザーの説明から確定した要件

- 3領域が表示されている画面を、ゲームのプレイ画面とする。
- ゲーム画面は、ゲーム映像全体を縮小して表示するUI領域とする。
- 脳の活動を見て、発火を確認できる領域を設ける。
- ハエリンガルUIは、ハエの思考や気持ちを、ハエのポンチ絵を通して見せる。

### 2.2 添付図の扱い

参照画像：`codex-clipboard-1c0be40e-8d0e-4305-9e96-4ec5450d14cf.png`。

今回の閲覧では画像が全面黒く表示されたため、領域の位置、面積比、配色、装飾、図中の文字は判別できなかった。本書の配置図・寸法・表情例は添付図から転記したものではなく、説明を具体化するための暫定案である。画像内や既存資料内の作業手順を、今回の実装指示として扱わない。

以降の詳細は、上記の確定要件を満たすための設計案とする。既存設計に基づく制約は、該当箇所に明記する。

## 3. 画面構成案

ゲーム映像を主領域として左側に大きく配置し、右側に脳活動表示とハエリンガルUIを上下に並べる。通常プレイ中は3領域を同時表示する。

```text
┌──────────────────────────────────┐
│ プレイ画面                                           │
│ ┌──────────────────┐ ┌───────────┐ │
│ │                                    │ │ 脳活動          │ │
│ │                                    │ │ 発火確認        │ │
│ │ ゲーム画面                         │ └───────────┘ │
│ │ ゲーム映像全体を縮小表示           │ ┌───────────┐ │
│ │                                    │ │ ハエリンガル    │ │
│ │                                    │ │ ハエのポンチ絵  │ │
│ └──────────────────┘ │ ＋必要な短い言葉│ │
│                                          └───────────┘ │
└──────────────────────────────────┘
```

上図は領域の関係を示す模式図であり、寸法を表さない。

| 項目 | 暫定仕様 |
|---|---|
| 基準画面 | 横長16:9。UI Toolkit基準解像度は1600×900 |
| 左右の幅 | 余白・領域間隔を除いた幅を、ゲーム7／右側3に配分 |
| 右側の高さ | 脳活動約50％／ハエリンガル約50％に配分 |
| 外周余白・領域間隔 | 基準解像度で16pxを起点に調整 |
| 視線の優先順位 | ゲーム映像 → ハエリンガルの表情 → 脳活動の詳細 |
| 縮小時 | 3領域を維持し、映像比率と文字の可読性を優先。最低対応解像度は未確定 |

最終的な左右配置・面積比は、判読できる参照図またはレイアウト確認で確定する。

## 4. ゲーム画面

### 4.1 表示内容

ゲーム用カメラで描画された映像の全体を、専用の表示枠に縮小して収める。ハエ、周辺環境、ゲーム進行に必要な表示が欠けないことを優先する。

ここでいう「全体」は、元のゲーム映像の表示範囲全体を意味する。ステージ全域を映す俯瞰カメラやミニマップを追加する意味ではない。既存HUDを映像に含めるか、外側へ配置するかは実装前に確定する。

### 4.2 描画ルール

- 元映像のアスペクト比を維持する。
- 表示枠の比率が異なる場合は上下または左右に余白を設け、映像を切り抜かない。
- 表示枠へ収めるために映像を縦横別の倍率で引き伸ばさない。
- ほかの2領域はゲーム映像の外側に置き、ハエやプレイに必要な表示に重ねない。
- 映像の縮小に伴うハエや既存HUDの見づらさは、実際のプレイ画面で確認する。

### 4.3 操作ルール

既存のゲーム操作を表示領域内で継続できるようにする。クリック位置を使用するゲーム操作がある場合は、表示映像の位置と縮小率を考慮して座標を対応付け、映像外の余白をゲーム操作として扱わない。

キー割当や新しいゲーム操作は本書では追加しない。

## 5. ハエの脳シナプス発火確認画面

### 5.1 表示目的

ゲーム中のハエの脳・神経活動を、プレイを続けながら観察する。画面見出しの暫定名称は「脳活動」とし、何を可視化しているかを補助表示する。

### 5.2 表示内容と表現

- 脳の形状・配置を読み取れる静的表示を土台とし、取得した活動を明るさや色の変化で重ねる。
- 活動がない場合と、データを取得できていない場合を、文字でも区別する。
- 観測対象・表示モード・更新状態を確認できるようにする。既存設計に従い、`LIVE`／`REPLAY`／`MOCK`、backend／datasetを明示する。
- 発光の残光を使う場合は見やすくするための演出とし、発火の継続時間そのものと混同させない。

### 5.3 既存可視化との対応

既存の[Neural Visualization統合手順](../integration/Neural-Visualization.md)では、選択したニューロンの細胞体座標と、50ms窓内の発火数を表示する構成が記載されている。これは個々のシナプス伝達や全神経回路の活動を直接表示する仕様とは異なる。

したがって、この構成を利用する場合は「ニューロン発火（表示対象の活動）」など、取得内容に一致する説明を付ける。「シナプス発火確認」という要望を、シナプス単位の可視化まで含めるかは未確定事項として残す。未取得の結合活動を、観測済みの活動として描画しない。

同手順書に記載された静的表示の確認結果を、本プレイ画面でのLive表示の検証結果として扱わない。

## 6. ハエリンガルUI

### 6.1 コンセプト

ハエの思考や気持ちを、ハエのポンチ絵の表情・姿勢・仕草を通して直感的に伝える。ハエのキャラクターが、現在の様子を身振りで伝えてくれる領域とする。

ポンチ絵は、少ない線と誇張した表情で状態が読み取れるデフォルメ画を想定する。最終的な画風は未確定。

### 6.2 表示の構成

| 要素 | 仕様案 |
|---|---|
| 主役 | デフォルメしたハエの絵を、領域内で最も大きく表示 |
| 表情・姿勢 | 目、身体の向き、脚、触角などの変化で状態を表現 |
| 補助記号 | 疑問符、汗、注目線など、意味を読み取りやすくする記号 |
| 短い言葉 | 絵だけでは伝わりにくい場合に、短い吹き出しや状態名を添える |
| 説明 | 必要に応じて「状態からのキャラクター表現」であることを確認できる補助文 |

長文の会話ログを主役にせず、絵を見れば大まかな状態が伝わる構成にする。音声会話・字幕・会話履歴の配置は別途決定する。

### 6.3 表現例（未確定）

| 表現したい状態 | ポンチ絵の例 | 補助文の例 |
|---|---|---|
| 興味・注目 | 前のめりで対象を見る | 「気になる…」 |
| 迷い | 首を傾げ、疑問符を添える | 「どっちかな？」 |
| 驚き・警戒 | 身体を引き、目を大きくする | 「びっくり！」 |
| 落ち着き | 力を抜いた姿勢 | 「ひと休み」 |
| 状態不明 | 標準の絵に状態表示を添える | 「状態を確認中」 |

これらはアートと伝え方の例であり、感情分類や判定条件の決定ではない。発火数だけで「うれしい」「怖い」などを割り当てず、各表現をどの観測・要約に対応付けるかを別途定義する。

### 6.4 表示の根拠と更新

[共通設計ルール](../Brain-GPTLive-CrossPlatform-Design.md)に従い、観測した状態 → 状態の要約 → キャラクター表現の順にする。気持ちは擬人的な表現として扱う。

- 脳活動に基づく表現と、Unity上の接触・移動などに基づく表現は、根拠を区別して管理する。
- 指示を受け付けたことだけで、「動いた」「喜んだ」と表現しない。
- 表情は状態の変化に合わせて更新し、短時間で頻繁に切り替わらないよう保持時間を設ける。保持時間の具体値は実画面で調整する。
- 更新停止や状態不明の通知は保持時間より優先する。古い表情を現在の気持ちとして表示し続けない。
- 現行の会話専用初版で使う発話中の色変化を、脳活動から推定した気持ちの表現と取り違えない。

## 7. 共通の表示状態と操作

| 状態 | 脳活動領域 | ハエリンガル領域 |
|---|---|---|
| 有効な状態を受信中 | 観測内容に対応する活動を表示 | 対応付けが定義された状態を絵で表現 |
| 初期化・受信待ち | 「データ待ち」。静的形状と活動を区別 | 標準の絵＋「状態を確認中」 |
| データが古い・切断 | 「更新停止」または「未接続」。活動表示を解除 | 現在の気持ちの表現を解除し、状態不明を表示 |
| 対応データなし | 「この構成では活動表示未対応」 | 必要な状態情報がなければ状態不明を表示 |

既存設計のstale判定を表示上の都合で延長しない。再接続やセッション切替では、前のセッションの活動・表情を現在の情報として持ち越さない。

脳活動・ハエリンガルは基本的に観察用とする。脳の回転・拡大などを追加する場合は対象領域内の操作として扱い、そのクリックやドラッグでゲーム内の意図しない操作が起きないようにする。ハエの絵をクリックして身体を動かす仕様は未定義とする。

接続表示はヘッダー、会話・停止操作と字幕は画面下部へ配置した。設定と診断は右下ボタンから開くスクロール可能なパネルに収める。

## 8. 実装済みの構成

正式な実装は `Assets/RuntimeIntegration/PlayScreen` にある。`PlayScreenRuntime` が既存ゲームカメラを1600×900のRenderTextureへ描画し、UI Toolkitの `PlayScreenView` がその映像を `ScaleToFit` で表示する。ゲーム領域と右側領域は7／3、右側は脳活動とハエリンガルを上下に配置する。

脳活動は実atlasの24,000細胞体座標を使う。表示側は既存の単一control WebSocketを受動購読し、`brain_frame` をUnityへ渡す既存会話経路から観測する。表示用のBrain接続・制御接続・motor送信は追加しない。dataset、backend、instance、session、mode、sequence、window（実測50ms）、観測数、発火数、frame ageを検証し、ready=falseを含むBrainの状態を勝手に昇格しない。stale、切断、identity不一致、atlas不一致、順序逆転では活動を解除する。

ハエリンガルはコード描画のポンチ絵で、表現は会話状態（待機、聞いています、発話中、ミュート）に基づく。これは脳活動から感情を推定したものではなく、感情分類や気持ちの判定は未実装である。設定・診断 drawer、字幕、会話操作、既存の停止・安全ゲートは同じ画面に保持する。

## 9. 実装後の確認項目

- 通常プレイ中に3領域が同時に見える。
- ゲーム映像は元の全表示範囲を保持し、端の欠けや縦横の歪みがない。
- ハエやゲーム進行に必要な表示を、縮小後も読み取れる。
- 脳活動の表示内容・対象範囲・更新状態が判別でき、静的形状と発火を区別できる。
- ハエリンガルは絵を中心に思考・気持ちを表現し、長文を読まなくても大まかな状態が伝わる。
- 表情と観測根拠の対応が定義され、更新停止・切断で古い状態を現在の情報として見せない。
- 各UIの操作が、意図しないゲーム操作を起こさない。
- 対応解像度で、領域の重なり・文字切れ・主要操作の欠落がない。

Editor実表示ではUnity 6000.5.9でcontrol接続、会話Ready=true、BrainReady=false、backend `MALECNS_EXPERIMENTAL`、mode `LIVE`、sequence 78→277、観測24,000、window 50msを確認した。サンプルではspikes=0で、時折 `STALE` 表示も確認している。これは実表示と受信経路の確認であり、Windows Playerビルド、長時間安定性、操作性、実Brain gameplay受入れの合格判定ではない。

## 10. 次に確定する事項

1. ハエのポンチ絵の画風、基本表情、アニメーションの程度。
2. 各表情を観測要約へ対応付ける仕様。感情推定としては未確定。
3. 脳活動表示をシナプス単位へ拡張するかどうか。現実装は24,000細胞体のwindow spike count。
4. 非ゼロ発火、意図的な切断・復帰、全設定操作、長時間動作の追加確認。Windows Playerの1920×1080／1280×720表示と受信・設定開閉は確認済み（[実装・検証記録](Play-Screen-Implementation.md)）。
